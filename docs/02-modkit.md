# 2. SporeKit и мод-тулкит

## 2.1 API для модов (C ABI)

Мод — обычная 32-битная DLL, экспортирующая одну функцию:

```c
SPOREKIT_EXPORT const SkModInfo* sporekit_mod_main(const SkHost* host);
```

`SkHost` — таблица функций SporeKit (версионированная, `host->abi_version`):

| Группа | Функции |
|---|---|
| лог | `log(level, fmt, ...)` → `mods/logs/sporekit.log` + буфер консоли |
| символы | `sym(name)` → адрес с учётом ребейза или 0; `sym_require(names[])` |
| хуки | `hook_create(target, detour, &orig)`, `hook_enable/disable/remove` — привязаны к моду и снимаются при выгрузке |
| события | `subscribe(event, cb, user)` — preinit / init / post_init / frame / shutdown |
| команды | `command_add(name, help, fn, flags)` — команды консоли (и, через coop, в консоли читов игры) |
| главный поток | `run_on_main(fn, user)` — выполнить в следующем кадре |
| конфиг | `config_get(section, key, default)` из `mods/<mod>.ini` |
| D3D | `d3d_device()`, событие `overlay` для рисования поверх кадра |

`SkModInfo` содержит имя, версию, `on_unload`. Хелперы C++ для вызова функций игры
(`thiscall`/`cdecl`/виртуальные по индексу) — в `sdk/include/sporekit_game.hpp`.
Классы игры **не** объявляются как C++-классы (у mingw другой ABI vtable) — доступ
к полям идёт по смещениям, вызовы — через типизированные указатели функций.

## 2.2 Консоль разработчика (devkit)

SporeKit поднимает TCP-сервер `127.0.0.1:47800` (+N для экземпляра N, см. 6).
Протокол — строка-команда → одна строка JSON `{"ok":true,"out":"..."}`.
Команды по умолчанию выполняются в главном потоке игры (между кадрами);
команды с флагом `ANY_THREAD` (`ping`, `log`, `threads`, `stack`) работают даже если
игра зависла — так видно, где именно.

Встроенные команды:

| Команда | Что делает |
|---|---|
| `help`, `info` | список команд; версия, хэш exe, база, FPS, номер кадра, моды |
| `log [n]` | последние строки лога |
| `sym <имя|адрес>`, `sym.find <подстрока>` | поиск в базе символов |
| `mem.read <адрес> <len>`, `mem.write <адрес> <hex>` | память процесса |
| `mem.ptr <адрес> <off>...` | разыменовать цепочку указателей |
| `call <адрес|символ> <cdecl|stdcall|thiscall> [args]` | вызвать функцию игры (RE-эксперименты) |
| `cheat <строка>` | выполнить чит через `App::cCheatManager` (переходы по этапам, ДНК…) |
| `shot [путь]` | скриншот back-buffer в PNG (путь Linux, по умолчанию `out/shots/`) |
| `key <vk> [tap|down|up]`, `text "..."`, `click x y`, `move x y` | ввод в окно игры |
| `mods`, `mod.reload <имя>`, `mod.unload`, `mod.load` | управление модами |
| `game.mode` | активный режим игры (меню, существо, редактор…) |
| `stack` | стек главного потока (для зависаний) |
| `hangdump` | стек главного потока с именами DLL в лог (работает и под loader lock) |
| `exc [clear]` | исключения, пойманные логгером (адрес, ближайший символ, регистры) |
| `bg on\|off` | фоновый режим: игра рисует без фокуса окна |
| `wait.frames <n>` | дождаться n кадров |
| `quit` | закрыть игру |

Моды добавляют свои команды (`coop.*`).

### Мост в консоль читов Spore

SporeKit регистрирует в самой игре (консоль `Ctrl+Shift+C`) чит `sk <команда devkit>`
(например `sk info`), а моды — свои ключевые слова через `host->cheat_register`:
`coop host` превращается в devkit-команду `coop.host`, вывод печатается в консоль игры.
Чит реализован как поддельный `ArgScript::ICommand` с вручную собранной MSVC-vtable.

### Диагностика

* **Логгер исключений** (VEH): access violation и т.п. логируются один раз на адрес с
  ближайшим символом из базы — Wine часто глотает исключения в оконных колбэках,
  и без этого игра просто «замирает».
* **Сторожевой поток**: если главный поток не продвигается 15–30 с или loader lock
  удерживается >10 с, в лог пишется стек виновника.
* **Запасной канал главного потока**: задачи консоли выполняются не только в `Present`, но и
  через сообщение окну (`WM_APP+0x5C0`), поэтому команды работают на загрузочных экранах и
  когда кадры не рисуются.

## 2.3 `sporectl` (Linux)

`tools/sporectl.py` — клиент консоли. Примеры:

```bash
sporectl info
sporectl sym.find GetAvatar
sporectl mem.read 'Simulator::cGameNounManager::Get' 32
sporectl cheat "addDNA 1000"
sporectl shot                    # → out/shots/shot-<время>.png
sporectl wait-mode Creature 120  # ждать перехода в режим (опрос game.mode)
sporectl -i 2 coop.status        # экземпляр №2 (порт 47801)
```

Также используется из автотестов (`tools/tests/*.py`).

## 2.4 Горячая перезагрузка

`make coop && sporectl mod.reload coop`:
1. SporeKit вызывает `on_unload` мода, снимает все его хуки и подписки, удаляет команды.
2. `FreeLibrary`, копирует свежую `coop.dll` в `mods/.shadow/coop-<n>.dll`, грузит её
   (оригинал остаётся незаблокированным — сборка может его перезаписывать).
3. Вызывает `sporekit_mod_main` → мод заново инициализируется прямо в текущем режиме игры.

Мод сам отвечает за то, чтобы при выгрузке удалить созданные им игровые объекты
(у coop — заспавненных «марионеток»).

## 2.5 Скриншоты и оверлей

Хук `Present` даёт доступ к устройству D3D9: `shot` копирует back-buffer
(`GetRenderTargetData`) и пишет PNG. Оверлей (текст поверх игры: статус сессии,
ники над существами, чат) рисуется в том же хуке до вызова оригинального `Present`.

## 2.6 Многоэкземплярный режим

Ключ командной строки `-sporekit-instance:N` (N≥2; Bottles фильтрует переменные окружения):
* порт консоли `47800+N-1`, порт coop по умолчанию `47810+N-1`;
* профиль `instN`: хук `SHGetFolderPathW` → данные Spore в `AppData/Roaming/SporeKit-instN`
  (свои сохранения и кэши, без конфликтов блокировок); `-sporekit-profile:<имя>` — то же
  для любого имени (тестовый профиль `test`);
* обход проверки единственного экземпляра: переименование мьютексов `CreateMutexA`
  (`Global\SporeEdi` и др.).

Так на одной машине запускаются хост и гость для полноценного теста.
